## 3. 使用方法

### 3.1 生成 manifest（在 E:\大创 或 Kaggle 上）
```bash
# 本地 4 病例快速验证
python downsample.py --data-root E:/大创/kits19_small --out-dir E:/大创/experiments \
    --fractions 0.10,0.20 --seed 42 --train-ratio 0.5 --val-ratio 0.25 --max-cases 4

# Kaggle 全量
python downsample.py --data-root /kaggle/input/datasets/user123454321/kits19-1 \
    --out-dir /kaggle/working/experiments --fractions 0.10,0.20 --seed 42
```
产出：`experiments/data10pct/manifest.json`、`experiments/data20pct/manifest.json`。

### 3.2 实验模式跑主代码（VSCode / Kaggle）
- VSCode：终端设置环境变量后启动 notebook，或直接在 notebook 里改 `EXPERIMENT_MANIFEST` 为 manifest 绝对路径：
  ```powershell
  $env:EXPERIMENT_MANIFEST = "E:\大创\experiments\data10pct\manifest.json"
  jupyter notebook
  ```
- Kaggle：在 notebook 模块4.5 顶部直接给 `EXPERIMENT_MANIFEST` 赋值（如 `/kaggle/working/experiments/data10pct/manifest.json`）。
- 不设置该变量 = 原默认模式（全量或本地快速验证），行为与之前完全一致。

### 3.3 产物规范（实验目录内）
| 文件 | 内容 |
|---|---|
| `manifest.json` | 本实验的病例划分（契约 C，唯一口径） |
| `best_unet.pth` | 最优模型权重 |
| `training_curves.png` / `prediction_samples.png` | 训练曲线与推理图 |
| `evaluation_metrics.csv` | 模块12 的 7 项指标表 |
| `metrics.json` | 契约 D 统一指标：实验信息 + 最优验证 Dice/IoU + 测试集指标 |

## 4. 口径与注意事项

- **测试集冻结**：test 始终取全量划分的测试病例，各比例间完全一致，不做降采样。
- **seed=42 固定**，manifest 里记录 seed 与划分比例（`train_ratio/val_ratio/test_ratio/max_cases`），可完全复现。
- 按病例划分，禁止同一病例切片跨集合（避免数据泄漏）。
- 实验模式下训练集 `drop_last=False`（小样本只有 1-2 例时保留唯一批次）。
- **修改划分逻辑时，必须同步 notebook 模块4 与 `downsample.py` 两处**（当前刻意保持逐行一致）。
- 本地 4 病例的 10%/20% 实验都只剩 1 个训练例，只能验证流程，**真实对比必须在 Kaggle 全量上跑**。
