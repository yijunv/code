## 3. 使用方法

### 3.1 生成 manifest（通常不用手跑）

模块1.5 会自动调用 `downsample.py` 生成。手跑命令：

```bash
# 本地 4 病例
python downsample.py --data-root E:/大创/kits19_small --out-dir E:/大创/experiments --fractions 0.10,0.20 --seed 42 --train-ratio 0.5 --val-ratio 0.25 --max-cases 4

# Kaggle 全量
python downsample.py --data-root /kaggle/input/datasets/user123454321/kits19-1 --out-dir /kaggle/working/experiments --fractions 0.10,0.20 --seed 42
```

产出：`experiments/data10pct/manifest.json`、`experiments/data20pct/manifest.json`。

### 3.2 三种跑法详解

**① Kaggle 全量 baseline**
- 导入 notebook：File → Import Notebook → GitHub → `yijunv/code` → `总模型代码进行中.ipynb`；右侧 Settings 确认 Accelerator=GPU T4 x2、Internet 开启（元数据已默认，一般不用动）。
- 运行顺序：模块0 → 模块1 → 模块1.5 → 模块2 → … → 模块13。
- 模块1.5 会自动 `git clone` 仓库到 `/kaggle/working/code`（GitHub 导入只带 notebook 本身，不带 `downsample.py` / `src/`）。

**② Kaggle 小样本实验（10% / 20%）**
- 在模块1.5 运行前，先执行（单独 cell 或模块1.5 顶部加一行）：
  ```python
  os.environ["RUN_EXPERIMENTS"] = "1"   # "1" = 10%，"2" = 20%
  ```
- 再运行模块1.5：自动完成 clone → `downsample.py` 生成 manifest → 设 `EXPERIMENT_MANIFEST`。
- 产物落在 `/kaggle/working/experiments/data10pct|data20pct/`。

**③ 本地 VS Code 冒烟**
- 默认：模块1.5 全部跳过，行为与旧版完全一致（`kits19_small` 4 例）。
- 想验证实验链路：同样设 `RUN_EXPERIMENTS=1/2` 后运行模块1.5（4 例只能验证流程，不代表真实效果）。

> 备选（兼容旧做法）：模块4.5 顶部直接给 `EXPERIMENT_MANIFEST` 赋绝对路径同样可启用实验模式，两者等效；本地不建议在终端 `$env:` 设变量（Jupyter 内核不继承）。

## 4. 口径与注意事项

- **测试集冻结**：test 始终取全量划分的测试病例，各比例间完全一致，不做降采样。
- **seed=42 固定**；manifest 记录 seed 与划分比例，可完全复现。
- 按病例划分，禁止同一病例切片跨集合（避免数据泄漏）。
- 实验模式下训练集 `drop_last=False`（小样本保留唯一批次）。
- **改划分逻辑必须同步 notebook 模块4 与 `downsample.py` 两处**。
- 本地 4 例的 10%/20% 只能验证流程；**真实对比必须在 Kaggle 全量上跑**。
- 熵相关指标目前是占位值，等贝叶斯 mc_predict 接入后才真实。
